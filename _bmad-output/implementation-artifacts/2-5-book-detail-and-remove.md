# Story 2.5: Book detail and remove

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a reader,
I want a detail screen for each book and the ability to remove it,
so that I can see metadata and manage my library (FR25).

This is the **library-management UI** of Epic 2, built on the shell stood up by 2.3/2.4. Stories 2.1–2.4 produced the import pipeline, the drift `Books`+`Chapters` schema, the flat-file `stream_store` (with `delete`/`deleteCover`), the Riverpod provider seam, and `LibraryScreen` with cover-thumbnail rows. **This story adds no parsing and no schema columns.** It introduces the app's **second screen** (`BookDetailScreen`, reached by tapping a library row — the app has no router today, so this story also establishes `Navigator.push`-based navigation), two **read queries** the detail screen needs (`watchBookById`, `chaptersForBook`), a small **`LibraryService.removeBook`** that coordinates the already-built deletion primitives (drift cascade + stream file + cover file) behind the `ui/ → services/ → data/` layering, and the **Remove** + **Restart** + (inert) **Send-to-watch** / **jump-to-chapter** actions.

**Scope guardrail:** book-detail screen + chapter list + Remove (fully functional) + Restart (confirm dialog only; the reposition effect is **Epic 4**) + Send-to-watch and jump-to-chapter rendered **visibly disabled/inert** (Epic 4). **NOT** in scope: the `Positions` table / real progress % / time-remaining / last-read (**Epic 4 / 4.5** — these stay placeholders, exactly as the library row already shows `0%` / "Not started"); the actual reposition-and-resync behind Restart and jump-to-chapter (**Epic 4**, rides the existing `position` message — architecture.md:194,591); the transfer engine / Send-to-watch action (**Epic 4**); content dedup on re-import (**deferred product decision** — deferred-work.md, not an AC here); the inline import-failure messaging + ugly-corpus suite (**2.6**). Do **not** pull Epic-4 progress/sync forward — wire the buttons inert and keep the progress area a placeholder.

## Acceptance Criteria

1. **AC1 — Book-detail screen with cover, metadata, progress placeholder, chapter list.** Given a library row, when I tap it, then a `BookDetailScreen` opens showing the **cover** (when `cover_path` is set; placeholder when null), **title**, **author** (omitted when null), other metadata available without Epic 4 (e.g. chapter count, total words), a **progress area** (% + time-remaining **placeholder** until Epic 4 — consistent with the row's `0%` / "Not started"), and the **chapter list** (one entry per `Chapters` row, in `chapterIndex` order, showing the chapter title). [Source: epics.md#Story-2.5 lines 493-495; UX-DR19 epics.md:175; DESIGN.md:86-87,157; EXPERIENCE.md:54,59; FR23]
2. **AC2 — Actions present; Send-to-watch and jump-to-chapter visibly inert until Epic 4.** Given book detail, when I view the actions, then **"Send to watch"** (prominent M3 **filled** button), **Restart book**, and **Remove** are present — and **Send-to-watch** and **jump-to-chapter** (chapter-row tap) render **visibly disabled (inert)** (e.g. `onPressed: null` greyed filled button; chapter rows non-tappable / disabled affordance) so there is **no dead button that appears functional**. [Source: epics.md#Story-2.5 lines 497-499; UX-DR19 epics.md:175 "Send to watch (prominent M3 filled button)"; DESIGN.md:157 "Send to watch as the prominent M3 filled button; Restart and Remove behind lower-emphasis actions"]
3. **AC3 — Remove deletes rows + stream file + cover file and disappears from library.** Given a book, when I Remove it, then its **drift rows** (`Books` + cascaded `Chapters`), its **stream file** (`<fingerprint>.stream` + sibling `.jsonl`), and its **cover file** (when `cover_path` set) are all deleted, and it **disappears from the library** (the reactive `libraryProvider` stream drops it) and the detail screen returns to the library. Removal is **idempotent-safe** (a missing file does not throw). [Source: epics.md#Story-2.5 lines 501-503; FR25; database.dart:89-92 `deleteBookCascade`; stream_store.dart:112-117,121-133 `deleteCover`/`delete`; architecture.md:452 layering]
4. **AC4 — Restart book asks once; effect deferred to Epic 4.** Given Restart book, when I tap it, then it **asks once** (a single M3 confirmation dialog) before confirming. The actual **reposition** (set absolute word index → 0 + re-sync the watch) **lands with sync in Epic 4** — in 2.5 there is no `Positions` table, so confirming performs **no persisted state change**; the dialog wiring is the deliverable and confirm simply dismisses. [Source: epics.md#Story-2.5 lines 505-507; EXPERIENCE.md:87 "Restart asks once"; architecture.md:194,579,591 (repositions ride the `position` message — Epic 4); decision-log.md:32]

## Dev Notes

### What this story IS / ISN'T
- **IS:** `BookDetailScreen` (cover header, title/author/metadata, **placeholder** progress, chapter list); the app's **first navigation** (`Navigator.push` from the library row — no router); two drift reads (`watchBookById`, `chaptersForBook`); `LibraryService.removeBook` coordinating `deleteBookCascade` + `store.delete` + `store.deleteCover` behind the layering; the **Remove** confirm-and-delete flow (fully functional, AC3); the **Restart** confirm dialog (AC4, effect deferred); **Send-to-watch** (filled button) and **jump-to-chapter** rendered **inert** (AC2). Resolves the **2.3-deferred `StreamStore.delete()` jsonl-surgery** concern (document-the-accept + locking test).
- **ISN'T:** the `Positions` table / real progress % / time-remaining / last-read (**Epic 4 / 4.5** — placeholders only); the actual reposition behind Restart + jump-to-chapter (**Epic 4**, rides the `position` message); the transfer engine / Send-to-watch action (**Epic 4**); content dedup (**deferred product decision**); inline import-failure copy + ugly-corpus suite (**2.6**); a route table / `go_router` (`Navigator.push` suffices for two screens); the active-on-watch row marker (Epic 4). Do not pull these forward.

### Remove — ordering, layering, idempotency (AC3)
- **Layering (architecture.md:452):** `ui/` must not import `drift`/`stream_store` directly. Reads flow `widget → provider → drift` (matches the existing `libraryProvider`). The **mutation** flows `widget → ref.read(libraryServiceProvider).removeBook(book) → AppDatabase + StreamStore`. `LibraryService` is the new `services/library/` seam (constructor-injected — architecture.md:285).
- **Order = drift rows first, then files.** Rationale: the user-visible AC is "disappears from the library" — the reactive `watchAllBooks` stream fires on the row delete. A subsequent file-delete failure leaves an orphan *file* (benign local-disk leak), never an orphan *row → missing stream* (which would break Send-to-watch later). Deletes are idempotent (missing file ≠ throw), so the normal path never errors; an unexpected error **propagates** (no silent `catch {}` — architecture.md:293).
- **2.3-deferred jsonl-surgery (RESOLVED here = document-the-accept):** `Books.streamPath` is always `<fingerprint>.stream` per the `store.write` contract (stream_store.dart:58-84), so `delete()`'s no-`.stream`-suffix fallback branch is unreachable from the Books-row path. A `write → insertBook(streamPath) → removeBook` round-trip test locks the `.jsonl` deletion. **No column / schema bump** (carrying an explicit `jsonlPath` on the row is not justified). [Source: deferred-work.md (2.3 review, StreamStore.delete)]

### Restart & inert actions — what 2.5 ships vs Epic 4 (AC2, AC4)
- **Restart book (AC4):** ships the **confirm dialog only**. There is **no `Positions` table** in 2.5 (2.3 created only `Books`+`Chapters`), so "reset to word index 0" has nothing to write yet. The reposition (absolute word index → 0) and watch re-sync **ride the existing `position` message in Epic 4** (architecture.md:194,591; LWW chosen specifically so the UX's deliberate *backward* repositions — Restart + jump-to-chapter — are expressible, architecture.md:579). Confirm → dismiss; leave a `// TODO(epic-4)` marker.
- **Send-to-watch (AC2):** prominent M3 **`FilledButton`** rendered **disabled** (`onPressed: null`). The transfer engine + one-active-book + `BookChanged` are **Epic 4** (epics.md Story 4.3). Inert-not-absent so the screen reads complete but no button lies.
- **Jump-to-chapter (AC2):** chapter rows render but are **non-tappable / disabled** until Epic 4 maps `Chapters.wordOffset` → absolute word index → `position` re-sync (architecture.md:591). Showing the list is in scope; making it jump is not.
- The principle (epics.md:499): **no dead button that appears functional.** Disabled/greyed > present-but-silently-broken.

### Progress is a PLACEHOLDER (AC1) — do not fabricate it
- The library row already shows `LinearProgressIndicator(value: 0)` + "Not started" (library_screen.dart:200-205) because `lastReadEpochS` is null and there is no `Positions` table. The detail **progress area** matches that: a `value: 0` bar + plain placeholder text for "% + time remaining." Real progress, time-remaining (from the cumulative-duration array), and last-read land in **Epic 4 / 4.5** (FR16). Do **not** compute a fake % or a time-remaining from WPM (WPM is a watch-side Epic-3 setting).
